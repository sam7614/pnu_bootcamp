# 레퍼런스 및 증빙 표기 가이드 — 확정본

## 1. 원칙

- 참고 PDF는 문서명·연도·행사명·일자를 구체적으로 쓰는 방식을 사용한다. 본 프로젝트는 여기에 Source ID와 Evidence ID를 추가하여 추적성을 강화한다.
- 주장·수치·표·그림마다 원본 위치를 역추적할 수 있어야 한다.
- 사업계획, 실행자료, 공식 집계, 증빙을 서로 다른 근거 유형으로 구분한다.
- 계획 문서는 실적을 증명하지 않으며, 작업본은 공식 제출값을 확정하지 않는다.

## 2. 식별자

- Source ID: `SRC-001`부터 순차 부여
- Evidence ID: `EVD-001`부터 순차 부여
- Issue ID: `ISS-001`부터 순차 부여
- Review ID: `REV-001`부터 순차 부여
- Figure ID: `FIG-001`부터 순차 부여
- ID는 삭제 후 재사용하지 않는다.

## 3. 내부 원고 표기

```text
[근거: SRC-005 / 사업계획서 / p.00]
[근거: SRC-007 / 0. 성과지표 현황!A1:X32 / 작업본·검증전]
[증빙: EVD-001 / 증빙자료집 p.00(편집 후)]
[그림: FIG-001 / 2026-00-00 / 촬영자·제공부서]
[확인필요: 산정 기준일, 분모, 공식 제출본 여부]
```

## 4. 표·그림·사진 출처

- 표 아래: `자료: SRC-000, 문서명, 페이지/시트·범위, 기준일.`
- 가공 표: `자료: SRC-000을 바탕으로 사업단 재구성(산식: …).`
- 그림 아래: `그림 00. 제목(자료: 기관명, 문서명, 연도, SRC-000).`
- 사진 캡션: `프로그램명 | YYYY.MM.DD. | 장소/과정 | 장면 설명 | EVD-000.`
- 인터넷 자료는 공식 기관명, 페이지 제목, URL, 확인일을 함께 기록하되 최종 보고서는 제출 지침에 맞춘다.

## 5. Source 등록 필수정보

- 정확한 파일명·원본 경로·등록 사본 경로
- 문서 종류·발행기관·작성일·버전·적용 사업연도
- 관련 목차와 실제 사용 페이지/표/시트·셀 범위
- 개인정보·재정정보 등의 보안등급
- 중복본·개정본·승인 관계와 SHA-256
- 검토자·검토일·공식성 확인상태

## 6. Evidence 등록 필수정보

- Evidence ID·제목·원본 Source ID
- 증명하는 주장·수치·목차·지표
- 원본 위치와 제출용 선정 페이지
- 개인정보 비식별·초상권·기업기밀 처리 여부
- 검토자·상태·증빙자료집 최종 페이지

## 7. 근거 우선순위

1. 제출기관 공문·협약·승인 문서
2. 기관 제출 공식 실적조사·정산 자료
3. 내부 결재 완료 문서·운영 결과보고
4. 회의록·출석·이수증·설문 원자료·사진
5. 참고자료·미승인 작업본·예측값

충돌 시 상위 근거와 더 최신의 승인본을 우선하고, 판단 근거를 `issues.csv`에 기록한다.

## 8. 제출본 전환

- 내부 ID는 검증용 원고에 유지한다.
- 증빙자료집 페이지 확정 후 본문·요약·성과지표 표의 페이지 참조를 일괄 갱신한다.
- `[확인필요]`가 하나라도 남은 수치·주장은 승인 원고로 처리하지 않는다.
- 제출 직전에 내부 메모, 파란 작성방법, 붉은 검토표시를 제거하되 검증 원고는 별도 보존한다.
