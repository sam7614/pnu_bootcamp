# 팀장 3 운영 규칙 — Ⅲ장 사업성과 달성도

## 1. 적용 범위와 팀 책임

이 문서는 `04_Team3_Performance/`에서 수행하는 Ⅲ장 「사업성과 달성도」의 분석·집필·검토에 적용한다. 팀장 3은 T3-01~T3-12 산출물의 책임자이며, 다음 사항을 보증한다.

1. 공식 연차실적보고서 양식의 목차, 【작성방법】, 표, 산식, 단위 및 증빙 요구사항을 빠짐없이 반영함.
2. 승인된 사업계획의 목표와 해당 보고기간의 실제 실적을 구분하여 비교함.
3. 모든 지표의 정의, 인정 범위, 분자·분모, 중복 처리, 기준일, 단위, 해당연차·누적 구분을 기록함.
4. 목표값·실적값·달성률을 공식 실적조사표 및 마스터 수치와 대조함.
5. 본문, 표, 추진실적 요약, 증빙 간 수치와 표현을 일치시킴.
6. 근거가 확인되지 않은 수치나 성과를 작성·추정·보정하지 않음.
7. 팀장 검토와 승인이 끝난 산출물만 통합 보고서 후보로 전달함.

상위 프로젝트 `AGENTS.md`, 공식 양식 및 공식 지침과 이 문서가 충돌하면 공식 양식·공식 지침과 상위 프로젝트 규칙을 우선한다. 작성 시점에 최신 적용 연차나 보고기간이 확정되지 않았으면 임의로 정하지 말고 `확인필요`로 관리한다.

## 3. 사용할 원천자료

원본은 `01_Source_Documents/` 아래에서 읽으며, 아래 자료를 우선한다.

- `04_Academic_Policies/`: 학칙·규정, 개정 전후표, 승인·시행 자료
- `05_Partner_Companies/`: 참여의사서, 협약, 기업 참여 및 협력 실적
- `06_Faculty_and_Staff/`: 참여교원·전담인력 명단, 임용·재직·업무분장 자료
- `08_Education_Programs/`: 교육과정 체계, 프로그램 계획·운영·결과 자료
- `09_Students_and_Completion/`: 모집·선발·출석·이수·이수증 발급 자료
- `10_Graduation_and_Employment/`: 배출, 취업대상자, 취업·창업 및 연계취업 자료
- `12_Satisfaction_and_Improvement/`: 설문지, 원자료, 유효응답, 분석·환류 자료
- `14_Official_Performance_Data/`: 공식 실적조사표, 성과지표 정의서, 목표값, 제출용 집계, 보완 요청
- `15_Events_Photos_and_Publications/`: 우수사례·운영성과를 입증하는 사진, 결과물, 홍보·보도 자료

공식 작성기준은 `00_Project_Control/01_Official_Templates/`, 문체·표·출처 표기 기준은 `00_Project_Control/02_Writing_References/`와 `00_Project_Control/04_Guidelines_and_Checklists/`를 함께 확인한다. 자료가 `00_Inbox_Upload_Here/`에만 있으면 먼저 등록·분류를 요청하고, 원본을 임의로 이동·삭제하지 않는다.

문서의 효력은 원칙적으로 ① 공식 지침·협약·승인 공문, ② 공식 제출자료·실적조사표, ③ 승인된 사업계획, ④ 원천 증빙, ⑤ 내부 취합표 순으로 판단한다. 같은 단계의 자료가 충돌하면 작성일·승인 여부·개정 이력을 확인하고 `issues.csv`에 등록하며, 확정 전까지 수치를 사용하지 않는다.

## 5. 지표 정의 및 산정 규칙

### 5.1 지표별 필수 필드

T3-01~T3-10은 값을 사용하기 전에 다음 항목을 모두 기록한다.

| 필드 | 작성 규칙 |
|---|---|
| 지표 ID·명칭 | 공식 양식·실적조사표와 동일하게 작성 |
| 공식 정의·근거 | 정의서명, 작성기관, 적용 연차, 페이지·시트·셀, Source ID 기록 |
| 인정 대상·제외 대상 | 자격, 상태, 기간, 프로그램 수준, 취업비대상자 등 포함·제외 조건 명시 |
| 측정 단위 | 명, 개, 건, 점, %, 식 등 공식 단위 사용 |
| 분자 | 실제 집계 대상을 문장으로 정의하고 원천 명부·집계표와 연결 |
| 분모 | 비율·평균 산정의 모집단을 정의. 단순 건수 지표는 `해당 없음`으로 명시하고 임의의 1을 넣지 않음 |
| 산식 | 공식 산식을 그대로 기록하고 반올림 자릿수·처리 방법을 명시 |
| 중복 처리 | 동일인·동일기업·동일 프로그램·동일 제도 건의 고유키와 중복 제거 기준 기록 |
| 기준일·대상기간 | `YYYY-MM-DD` 기준일과 시작일~종료일을 모두 기록 |
| 실적 구분 | `해당연차`와 `누적`을 별도 행·열로 관리하며 합산 관계를 검증 |
| 목표·실적·달성률 | 공식 목표, 검증 실적, 달성률을 구분하고 단위 일치 여부 확인 |
| 상태 | `완료`, `진행중`, `예정`, `확인필요`, `대상기간 외` 중 하나 |
| 근거·증빙 | Source ID, Evidence ID, 원본 위치, 페이지·시트·셀 기록 |
| 검증·승인 | 계산자, 검산자, 검산일, 팀장 승인 상태 기록 |

### 5.2 공통 산정 원칙

- 공식 정의서와 공식 양식의 측정방법을 우선한다. 내부 관행이나 전년도 방식으로 대체하지 않는다.
- 건수·인원 지표의 실적은 공식 인정 조건을 만족하는 고유 대상 수다. 신청·선발·참여·수료·배출·취업을 서로 대체하지 않는다.
- 취업률 등 비율 지표는 공식 정의에 따른 분자를 공식 취업대상자 분모로 나누어 산정한다. 취업비대상자의 포함·제외 사유를 남긴다.
- 만족도는 학생·기업을 구분하고, 유효응답 수와 척도·환산식을 기록한다. 단순 응답자 수를 만족도 점수로 사용하지 않는다.
- 달성률은 공식 산식이 별도로 없을 때만 `실적값 ÷ 목표값 × 100` 적용 가능 여부를 팀장이 확인한다. 목표가 0이거나 정성지표이면 임의 계산하지 않는다.
- 해당연차 실적은 확정된 보고기간 안에서 인정된 실적만 포함한다. 누적 실적은 사업 시작일부터 기준일까지의 공식 인정 실적이며, 단순히 연차 실적을 더하기 전에 중복과 정정 이력을 검증한다.
- 기준일 이후 완료 예정인 활동은 `예정` 또는 `진행중`으로 쓰며 실적값에 포함하지 않는다.
- 반올림·절사·소수점 자릿수는 공식 지침을 따른다. 지침이 없으면 팀장이 기준을 확정하기 전 표시값을 확정하지 않는다.

## 6. 마스터 수치 단일원천

성과 수치의 단일원천은 `../06_Shared_Data/02_Master_Metrics/master_metrics.csv`다. 지표 정의는 `metrics_definitions.md`, 검증·변경 이력은 `metrics_validation_log.md`를 사용한다.

1. 본문·표·요약문 작성자는 마스터에서 `검증완료` 또는 팀장 승인 상태인 값만 가져온다.
2. 새로운 값이나 정정 필요를 발견해도 초안에서 직접 덮어쓰지 않는다. 원천 근거와 산정내역을 첨부해 공용 수치 수정 절차로 요청한다.
3. 마스터 값 변경 시 영향받는 T1·T2·T3·T4 목차, 추진실적 요약, 공식 실적조사표, 증빙을 함께 확인한다.
4. 같은 지표의 해당연차 값과 누적 값은 별도 레코드로 관리하고 `기준일`, `대상기간`, `단위`, `버전`을 반드시 포함한다.
5. 문서별 값이 다르면 다수결이나 최신 파일명만으로 선택하지 않는다. 승인 이력과 원천자료를 확인하고 이슈 해결 전에는 `확인필요`로 둔다.

## 7. 공식 실적조사표 대조

T3-01~T3-10의 값은 `14_Official_Performance_Data/`에 있는 적용 연차의 공식 실적조사표와 반드시 대조한다. 파일이 없거나 적용 연차가 불명확하면 `미확인`으로 기록하고 값을 확정하지 않는다.

대조표에는 최소한 다음 열을 둔다.

| 지표 ID | 단위 | 목표값 | 실적조사표 해당연차 | 실적조사표 누적 | 마스터 해당연차 | 마스터 누적 | 본문·표 위치 | 차이 | 원인·조치 | 확인자·확인일 |
|---|---|---:|---:|---:|---:|---:|---|---:|---|---|

대조 순서는 다음과 같다.

1. 공식 지표명, 단위, 목표값, 적용 연차와 기준일이 같은지 확인함.
2. 해당연차와 누적 열이 뒤바뀌지 않았는지 확인함.
3. 분자·분모와 산식, 중복 제외, 반올림 결과를 원천자료에서 재검산함.
4. 실적조사표 ↔ `master_metrics.csv` ↔ Ⅲ장 본문·표 ↔ 추진실적 요약의 값을 대조함.
5. 불일치는 `../06_Shared_Data/01_Registries/issues.csv`에 등록하고 원인·책임자·해결기한을 정함.
6. 불일치가 해소되고 변경 이력이 남은 뒤에만 팀장이 승인함.

공식 실적조사표의 값을 근거 없이 보고서 수치에 맞추거나, 보고서 수치를 실적조사표에 맞추기 위해 임의 보정해서는 안 된다.

## 8. 문체·표·근거·증빙 규칙

### 문체

- 공식 양식의 제목과 세부 구성을 변경하지 않는다.
- 기본 구조는 `□ 핵심 제목 → ◦ 주요 세부 실적 → - 계획·배경 / 실제 추진 / 참여 주체·일정 / 정량·정성 성과 / 목표 기여 / 개선·환류` 순으로 작성한다.
- 문장 종결은 `~함`, `~하였음`, `~되었음`, `~임`을 기본으로 하고, 과장·홍보성 표현과 근거 없는 인과관계를 피한다.
- 목표와 실적, 해당연차와 누적, 완료와 진행중·예정을 문장에서도 명확히 구분한다.
- T3-11·T3-12도 수치 나열에 그치지 않고 계획 대비 변화, 실행 과정, 확인된 성과와 확산·환류를 증빙에 근거하여 서술한다.

### 표와 그림

- 공식 양식의 지정 표를 최우선으로 사용하며 열·행·단위·주석을 임의 삭제하지 않는다.
- 모든 표에 표 제목, 기준기간 또는 기준일, 단위, 해당연차·누적 구분, 자료 출처, 관련 증빙을 표시한다.
- 계획, 목표, 실적, 달성률을 서로 다른 열로 구분한다. `0`, 공란, `해당 없음`, `미확인`을 같은 의미로 사용하지 않는다.
- 달성률·비율은 표에 표시된 분자·분모로 재계산 가능해야 한다. 본문 수치와 표 합계가 일치하는지 검산한다.
- 사진·그림에는 명칭, 일자, 관련 프로그램·활동, 출처, Evidence ID를 넣고 개인정보 노출 여부를 확인한다.

### 근거와 증빙

- 주요 주장과 수치에는 내부 작업 단계에서 `[근거: SRC-001 / 문서명 / p.00]`, `[증빙: EVD-001]` 형식을 연결한다.
- 문서명, 작성기관, 작성일, 버전, 페이지, 시트, 셀, 원본 경로까지 추적 가능하게 기록한다.
- 근거 자료와 증빙 자료를 구분한다. 근거는 산정·주장을 뒷받침하는 원천이고, 증빙은 최종 제출 시 제시할 확인 자료다.
- 개인정보·인사·취업 자료는 최소한으로 열람하고 본문·공개 산출물에는 비식별 정보만 사용한다. 원본 명부를 팀 산출물 폴더나 Git 추적 대상에 복제하지 않는다.
- 다른 사업·다른 연도·참고 보고서의 수치를 부산대학교 1차년도 실적으로 전용하지 않는다.

## 9. 작업 절차

각 담당자는 다음 순서를 지킨다.

1. 공식 양식에서 담당 목차의 【작성방법】, 지정 표, 산식, 필수 증빙을 추출함.
2. 승인 사업계획의 목표·측정방법과 변경 승인 이력을 확인함.
3. 관련 Source ID와 Evidence ID를 확인하고 자료 누락·충돌을 등록함.
4. 지표 정의, 분자·분모, 기준일, 대상기간, 해당연차·누적, 중복 기준을 작성함.
5. 원천자료 산정 → 독립 검산 → 공식 실적조사표 대조 → 마스터 값 확인 순으로 검증함.
6. 검증된 마스터 값으로 본문·표를 작성하고 모든 주요 주장에 근거·증빙을 연결함.
7. 담당자 자체점검 후 팀장 검토를 요청함.
8. 팀장 의견을 반영하고 재검산한 뒤 승인본을 `04_Team_Reviews/`에 남김.

## 10. 팀장 검토 및 승인

팀장은 다음 항목을 모두 확인한다.

- 공식 【작성방법】과 지정 표·산식·증빙 요구사항 충족
- 계획·목표와 실제 실적의 연결 및 변경 이력 반영
- 지표 정의, 분자·분모, 기준일, 대상기간, 단위, 중복 기준 명시
- 해당연차·누적 및 완료·진행중·예정 구분
- 원천자료 재계산, 공식 실적조사표, 마스터, 본문·표·요약 간 일치
- 문장구조·종결형·용어의 통일과 과장 표현 제거
- Source ID·Evidence ID의 정확성, 증빙 적절성, 개인정보 보호
- 연계 팀 목차의 동일 수치 및 설명과 일치
- 미확인 자료, 불일치, 개선 필요사항의 명시 및 해결 여부

검토 결과는 `../06_Shared_Data/01_Registries/review_results.csv`에 기록한다. 상태는 `검토요청`, `수정요청`, `재검토`, `승인`으로 관리하며, 승인 기록에는 산출물 경로·버전·검토자·승인일·잔여 이슈 여부를 포함한다. 하나라도 미충족이면 승인하지 않는다. 팀장이 `승인`한 동일 버전만 통합 보고서에 반영할 수 있다.

## 11. 미확인 지표값 금지

다음 행위는 금지한다.

- 원자료 없이 예시값, 추정값, 예상값, 임시 숫자, 전년도 값 또는 다른 사업 값을 입력하는 행위
- 자료 미제공·공란을 `0` 또는 `100%`로 처리하는 행위
- 분자·분모·기준일·대상기간이 확인되지 않은 비율이나 달성률을 계산하는 행위
- 진행중·예정 실적을 완료 실적에 포함하는 행위
- 동일인·동일기업·동일 건의 중복 여부를 확인하지 않고 합산하는 행위
- 실적조사표와 마스터의 불일치를 임의 수정하거나 숨기는 행위
- `확인필요`, `미확인`, `자료 미제공`을 최종 제출용 확정 수치처럼 표현하는 행위

값이 확인되지 않으면 숫자 칸을 억지로 채우지 말고 `미확인(사유: … / 필요자료: … / 확인담당: … / 예정일: …)`로 관리한다. 단, 공식 제출본에는 미확인 상태를 방치하지 않으며, 팀장 승인 전에 근거를 확보해 확정하거나 총괄책임자에게 쟁점으로 보고한다.

## 12. 완료 기준

목차별 작업은 다음 조건을 모두 충족해야 완료로 본다.

- 공식 작성방법 분석과 필수 항목 반영이 완료됨.
- 필요한 원천자료가 Source ID로 등록되고 주요 주장에 연결됨.
- 지표 정의와 산정내역이 재현 가능하며 독립 검산됨.
- 공식 실적조사표·마스터·본문·표·요약의 수치가 일치함.
- 증빙이 Evidence ID로 연결되고 개인정보 보호가 확인됨.
- 연계 팀과 공통 수치 대조가 끝남.
- 미해결 이슈가 없거나 총괄책임자가 명시적으로 처리 방향을 승인함.
- 팀장 3의 최종 승인이 `review_results.csv`에 기록됨.
