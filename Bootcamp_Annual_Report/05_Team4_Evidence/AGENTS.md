# 팀 4 증빙자료 운영 규칙

## 1. 적용 범위와 최우선 책임

이 문서는 `05_Team4_Evidence/`와 그 하위 폴더에서 수행하는 모든 증빙자료 작업에 적용함. 프로젝트 루트 `AGENTS.md`의 공통 규칙을 함께 준수하며, 충돌하지 않는 범위에서 이 문서의 증빙 관리 규칙을 더 구체적인 기준으로 적용함.

팀 4는 연차실적보고서의 본문·표·성과수치가 실제 원자료로 검증되도록 증빙을 등록, 선별, 비식별, 검토하고 최종 증빙 페이지까지 관리함. 팀 4의 책임은 문서를 많이 모으는 것이 아니라 다음을 충족하는 최소·충분한 증빙 묶음을 만드는 것임.

- 모든 주요 주장과 수치에 유효한 Source ID 및 Evidence ID가 연결되어 있음.
- 선택한 증빙이 해당 주장, 기준기간, 대상, 수치 및 완료 상태를 직접 입증함.
- 중복본과 개정본이 구분되고 최종 승인본이 식별됨.
- 개인정보와 재정 민감정보가 외부 제출본에서 안전하게 비식별 처리됨.
- 본문에서 증빙을 찾을 수 있고, 증빙에서 관련 본문을 역으로 찾을 수 있음.
- 최종 통합 편집 후 확정된 증빙 페이지가 원장 및 본문 표시와 일치함.

팀 4는 근거가 없는 내용을 보완하여 쓰거나 증빙처럼 보이도록 가공하지 않음. 문서의 진위·버전·내용을 확인하지 못한 상태에서는 `확인필요`로 관리하며 최종 증빙으로 승인하지 않음.

## 4. Source ID와 Evidence ID 연결 규칙

### 4.1 Source ID

Source ID는 원천 파일 단위의 고유 식별자이며 `SRC-001` 형식을 사용함. 신규 파일을 등록하기 전에 `source_registry.csv`에서 기존 등록 여부를 검색함. 다음 항목을 원본과 대조하여 기록함.

- 파일명, 문서명, 문서 종류, 발행기관, 문서일자
- 버전, 실적 기준기간, 관련 목차
- 원본 경로와 등록 복사본 경로
- 보안등급, 이전 개정본 Source ID, 체크섬
- 검토 상태, 검토자, 등록일

파일명이 달라도 체크섬과 내용이 같으면 별도 Source ID를 발급하지 않음. 내용 또는 승인 상태가 변경된 개정본은 새 Source ID를 발급하고 `revision_of_source_id`로 이전 Source ID와 연결함. Source ID는 삭제하거나 다른 파일에 재사용하지 않음.

### 4.2 Evidence ID

Evidence ID는 최종 보고서에서 하나의 주장 또는 관련 주장 묶음을 입증하기 위해 선택한 문서·페이지·시트·이미지 단위의 고유 식별자이며 `EVD-001` 형식을 사용함. 모든 Evidence ID는 반드시 하나 이상의 승인 가능한 Source ID에 연결되어야 함. 출처가 없는 Evidence ID는 생성하지 않음.

`evidence_registry.csv`에는 최소한 다음을 기록함.

- `evidence_id`, `evidence_title`, `source_id`, `evidence_type`
- 실제로 입증하는 주장 또는 수치(`proves_claim`)
- 관련 장과 `section_code`
- 원본 위치와 선정 사본 위치
- 개인정보 확인 결과와 비식별 상태
- 검토 상태·검토자·최종 증빙 페이지

한 Source ID에서 서로 다른 페이지나 입증 목적을 선택할 경우 Evidence ID를 나눌 수 있음. 하나의 Evidence ID가 여러 목차에 사용되면 관련 목차와 주장을 빠짐없이 기록하고, 각 본문 위치는 `reference_registry.csv`에 각각 등록함.

### 4.3 본문 표기

작업 원고에는 다음 형식을 사용함.

`[근거: SRC-001 / 정확한 문서명 / p.00 또는 시트명!셀범위]`

`[증빙: EVD-001]`

페이지가 없는 파일은 시트·셀, 문단 제목, 이미지 파일명, 회의 일자 등 재현 가능한 위치를 기록함. `p.00`, `추후 입력` 같은 자리표시자를 최종 승인 상태로 두지 않음.

## 5. 증빙 처리 절차

### 5.1 접수 및 원천 확인

1. `file_intake.csv`에 신규 파일과 탐지일, 원본 경로, 문서일자, 기준기간, 관련 목차를 기록함.
2. 파일이 정상적으로 열리는지, 페이지·시트가 누락되지 않았는지 확인함.
3. 발행기관, 결재·승인 여부, 작성일, 기준기간 및 문서 버전을 확인함.
4. 체크섬과 문서 메타데이터를 비교하여 중복본·개정본을 판정함.
5. 확인이 끝난 원천자료에 Source ID를 부여하고 `source_registry.csv`에 등록함.

### 5.2 증빙 선정

증빙은 다음 우선순위로 선정함.

1. 공식 기관이 발행·승인한 문서 또는 공식 시스템에서 추출한 자료
2. 보고 대상 기간과 산정 기준일이 명확한 자료
3. 주장과 수치를 직접 보여 주는 원자료
4. 문서명·일자·대상·단위·합계가 식별되고 판독 가능한 자료
5. 같은 내용을 입증하는 경우 개인정보 노출과 페이지 수가 더 적은 자료

계획서만으로 실제 이행을 입증하지 않으며, 모집 공고만으로 운영 완료나 이수 실적을 입증하지 않음. 회의 개최는 공문·회의록·결과보고서 중 실제 개최 사실과 결과를 확인할 수 있는 자료를 우선함. 사진은 행사명, 촬영일, 장소 또는 프로그램, 출처를 확인할 수 있을 때만 보조 증빙으로 사용함.

### 5.3 중복 및 개정본 관리

- 체크섬이 동일한 완전 중복 파일은 한 Source ID로 관리하고 중복 경로를 비고에 기록함.
- 내용은 같고 파일 형식만 다른 경우 원본성·가독성이 높은 파일을 기준본으로 선택하고 변환본 관계를 기록함.
- 개정본은 각각 Source ID를 부여하고 `revision_of_source_id`로 연결함.
- 승인된 최신 개정본을 우선하되, 해당 시점의 사실을 입증하려면 당시 유효한 구버전을 사용할 수 있으며 그 사유를 기록함.
- 폐기·취소·미승인·초안 버전은 최종 증빙에서 제외하고 상태를 명시함.
- 중복 또는 구버전이라는 이유로 원본 파일을 임의 삭제하지 않음.

### 5.4 선정 사본과 최종 페이지

선정 사본에는 입증에 필요한 페이지만 포함하고, 원본의 문맥을 왜곡하는 자르기·재배열·화질 저하를 금지함. 비식별 처리 외의 편집이 있으면 편집 내용과 원본 Source ID를 기록함.

`final_page`는 `07_Integrated_Report/`에서 본문과 증빙의 통합 편집이 완료된 뒤 실제 페이지를 직접 확인하여 입력함. 편집 완료 전에는 빈칸 또는 `미확정` 상태로 두며 예상 페이지를 기재하지 않음. 목차·표지·간지·증빙 삽입 순서가 바뀌거나 파일이 재생성되면 기존 페이지 승인을 무효화하고 전 Evidence ID의 페이지를 다시 대조함.

## 6. 개인정보 비식별 및 재정정보 보호

### 6.1 보호 대상

다음 정보가 포함된 원본은 보안자료로 취급함.

- 성명, 학번·사번, 생년월일, 주민등록번호, 연락처, 이메일, 주소, 서명·도장
- 출석부·성적·이수·취업·인사·급여 등 개인별 기록
- 계좌·카드번호, 거래 식별번호, 세금계산서의 불필요한 개인정보
- 기업 담당자 개인정보, 비공개 계약조건, 단가 및 내부 승인정보
- 그 밖에 개인 또는 기관을 불필요하게 식별할 수 있는 조합 정보

### 6.2 처리 원칙

- 민감 원본은 `99_Private_Local/` 또는 승인된 보안 위치에서만 관리하고 Git, 외부 공유 폴더, 공개 산출물에 넣지 않음.
- 원본에는 비식별 처리를 덮어쓰지 않으며, 제출용 사본을 별도로 생성함.
- 성명은 필요한 경우 비식별 코드 또는 집계값으로 바꾸고, 학번·계좌·연락처 등은 목적에 필요한 최소 부분만 남김.
- 검은 도형을 겹치는 방식처럼 복원 가능한 가림은 사용하지 않음. 내보낸 결과물에서 텍스트 검색·복사, 레이어, 메타데이터 및 확대 화면을 재확인함.
- 재정 증빙은 비목, 집행일, 승인된 금액과 합계를 입증하는 최소 범위만 공개하며 계좌번호, 카드번호, 개인 급여내역 등은 제거함.
- `personal_data_check`와 `redaction_status`를 모두 기록하고, 비식별 담당자와 별도의 검토자가 제출 사본을 재확인함.
- 보안 원본의 경로는 원장에 기록할 수 있으나 파일 내용이나 민감값을 일반 작업 문서에 복사하지 않음.

비식별로 인해 주장이나 금액을 검증할 수 없게 되면 단순 삭제하지 말고, 필요한 필드를 남긴 안전한 집계표 또는 공식 확인서를 요청하여 대체함.

## 7. 본문 주장·수치와 증빙의 양방향 추적

### 7.1 본문에서 증빙으로

팀 1~3의 각 주요 주장, 표 행 및 수치에 대해 다음 순서로 추적 가능해야 함.

`본문 파일·목차·주장/수치 → reference_registry.csv → Source ID·페이지/시트/셀 → Evidence ID → 선정 사본·최종 페이지`

`reference_registry.csv`의 `claim_or_metric`에는 모호한 제목이 아니라 실제 주장 또는 지표명, 기준기간, 단위를 식별할 수 있게 기록함. `used_in_file`, `chapter`, `section_code`, `page_or_sheet`, `cell_range`를 채워 제3자가 같은 근거를 다시 찾을 수 있게 함.

### 7.2 증빙에서 본문으로

각 Evidence ID에 대해 다음 역추적이 가능해야 함.

`Evidence ID·최종 페이지 → evidence_registry.csv의 proves_claim·chapter·section_code → reference_registry.csv → 사용 본문 파일·표·주장`

증빙 묶음에 들어갔지만 어떤 본문도 입증하지 않는 자료는 제외 후보로 분류함. 본문에서 참조하지만 선정 사본에 없는 Evidence ID는 누락으로 처리함.

### 7.3 수치 일치 검사

- 증빙의 대상 기간, 산정 기준일, 단위, 분모·분자, 합계가 본문과 일치하는지 확인함.
- 공통 수치는 `master_metrics.csv`의 승인값과 대조하고 팀별로 독립 수정하지 않음.
- 본문, 요약문, 성과지표표, 재정표, 증빙 간 값이 다르면 임의로 맞추지 않고 `issues.csv`에 등록함.
- 반올림 또는 집계 범위 차이가 있으면 계산근거와 표시 기준을 명시한 뒤 담당 팀장 승인을 받음.
- 표본·예시·계획값을 실제 전체 실적으로 오인할 가능성이 있는 증빙은 사용하지 않음.

## 8. 팀장 검토와 승인 절차

### 8.1 담당자 자체점검

T4-01~T4-04 담당자는 다음 항목을 모두 점검한 뒤 팀장에게 제출함.

1. Source ID와 원본 경로가 유효하고 파일이 열림.
2. 문서의 발행기관, 일자, 버전, 승인 상태 및 기준기간이 확인됨.
3. Evidence ID가 실제 주장과 수치를 직접 또는 타당하게 입증함.
4. 중복·개정본 관계와 최신 승인본 여부가 정리됨.
5. 개인정보 및 재정 민감정보 점검과 비식별이 완료됨.
6. 본문 표기, 공통 원장, 선정 사본의 ID가 일치함.
7. 관련 공통 수치가 `master_metrics.csv`와 일치함.
8. 최종 편집 단계에서는 실제 증빙 페이지가 대조됨.

### 8.2 팀장 검토

팀장은 `04_Evidence_Reviews/`의 검토자료와 실제 원본·선정 사본을 대조하고, `review_results.csv`에 실제 검토 결과를 기록함. 특히 `reference_accuracy`, `evidence_adequacy`, `cross_team_consistency`, `unverified_items_separated`를 확인함.

검토 결과는 다음 원칙으로 관리함.

- `승인`: 출처, 입증력, 보안, 추적성, 페이지가 모두 충족됨.
- `조건부 승인`: 보완 항목과 기한이 명시되고 최종 통합 전 재검토가 필요한 상태임. 최종 제출용 승인으로 간주하지 않음.
- `보완요청`: 누락, 불일치, 비식별 미완료 또는 버전 문제가 있음.
- `제외`: 관련성이 없거나 신뢰할 수 없거나 중복된 증빙임.

최종 증빙에는 팀장이 `승인`한 항목만 포함함. 승인 후 원본, 선정 페이지, 비식별 결과, 본문 주장, 수치 또는 통합 페이지가 바뀌면 승인은 자동으로 무효가 되며 재검토함. 팀장은 `evidence_registry.csv`의 `review_status`, `reviewer`, `final_page`와 `review_results.csv`의 결정이 서로 일치하는지 확인함.

### 8.3 최종 승인 게이트

최종 통합 직전에 다음 전수 점검을 수행함.

- 모든 본문 Evidence ID가 증빙 원장에 존재하는지 확인함.
- 모든 승인 Evidence ID의 Source ID가 출처 원장에 존재하는지 확인함.
- 선정 사본의 파일명·내용·증빙 순서와 원장 목록이 일치하는지 확인함.
- 개인정보·재정정보가 본문, 북마크, 주석, 첨부, 메타데이터에 남지 않았는지 확인함.
- 최종 PDF의 목차 페이지, 본문 증빙 표기, 증빙 간지 및 실제 페이지를 대조함.
- 열리지 않는 파일, 흐린 이미지, 잘린 표, 누락 페이지 및 빈 페이지가 없는지 확인함.

## 9. 미확인 증빙 금지

다음 자료는 확인이 끝날 때까지 Evidence ID의 최종 승인 대상이 될 수 없음.

- 원본 파일을 직접 열어 보지 않았거나 원본 경로를 확인할 수 없는 자료
- 발행기관, 작성일, 기준기간, 버전 또는 승인 여부가 불명확한 자료
- 출처를 알 수 없는 캡처, 재작성 표, 메신저 전달본 또는 임의 편집 이미지
- 내용이 잘렸거나 흐려서 대상·수치·단위를 판독할 수 없는 자료
- 계획·예정·신청 상태만 보여 주면서 완료 실적을 주장하는 자료
- 개인정보 비식별 또는 재정 민감정보 보호가 완료되지 않은 자료
- 본문 수치와 불일치하며 차이의 원인이 해결되지 않은 자료
- 최신 개정본 여부를 확인하지 못한 자료

미확인 자료는 본문 확정 근거로 사용하지 않고 `issues.csv`에 원인, 필요한 확인, 담당자와 기한을 기록함. 확인 전에는 `확인필요` 또는 `보완요청`으로 표시하며, 임의 추정·대체·숫자 보정·가상 증빙 생성을 금지함. 자료가 끝내 확보되지 않으면 해당 주장 또는 수치를 삭제·완화할지 총괄과 담당 팀장이 결정하도록 요청함.

## 10. 작업 완료 기준

팀 4의 작업은 파일을 모았다는 이유만으로 완료되지 않음. 다음 조건을 모두 충족할 때 해당 증빙 묶음을 완료로 보고함.

- 원천자료 등록, 중복·개정본 판정 및 Source ID 부여가 완료됨.
- Evidence ID별 입증 주장, 관련 목차, 원본·선정 위치가 등록됨.
- 개인정보·재정정보 점검 및 필요한 비식별이 이중 확인됨.
- 본문·수치와 증빙의 정방향 및 역방향 추적 검사가 통과됨.
- 팀장 검토 결과가 `승인`으로 기록됨.
- 최종 통합본의 실제 증빙 페이지가 확인되어 원장과 본문에 일치함.
- 남은 미확인·누락·불일치가 `issues.csv`에 공개되어 있으며 승인 항목과 섞이지 않음.

실제로 수행하지 않은 확인이나 검토를 완료로 기록하지 않음.
