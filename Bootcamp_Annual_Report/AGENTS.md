# 에이전트 운영 규칙

## 1. 프로젝트 목적과 적용 범위

이 프로젝트는 부산대학교 첨단산업 인재양성 부트캠프사업 1차년도 연차실적보고서를 공식 양식에 맞게 작성·검증·통합하기 위한 작업공간임. 이 문서는 프로젝트 루트와 모든 하위 폴더에 적용되며, 하위 팀의 `AGENTS.md`가 더 구체적인 규칙을 정한 경우 두 규칙을 함께 준수함.

## 2. 조직체계

- 총괄 AI 오케스트레이터: 전체 일정, 공식 기준, 공통 수치, 팀 간 충돌, 최종 통합을 관리함.
- 팀장 1: `02_Team1_Implementation/`에서 Ⅰ장 사업 추진 실적을 책임짐.
- 팀장 2: `03_Team2_Finance/`에서 Ⅱ장 재정투자 실적을 책임짐.
- 팀장 3: `04_Team3_Performance/`에서 Ⅲ장 사업성과 달성도를 책임짐.
- 팀장 4: `05_Team4_Evidence/`에서 증빙자료 등록·선정·검증을 책임짐.
- 팀원 ID와 세부 담당은 `06_Shared_Data/01_Registries/section_assignments.csv`에 기록함.
- 실제로 실행하지 않은 에이전트나 검토를 실행 완료라고 기록하지 않음.

## 3. 작업 순서

1. 공식 양식과 목차별 【작성방법】을 확인함.
2. 문장구조 및 기술방법을 확인함.
3. 승인된 사업계획과 변경계획을 구분함.
4. 실제 실적과 기준기간을 원자료에서 확인함.
5. 표와 산식을 작성하고 단위·분모·분자·기준일을 검산함.
6. 모든 주요 주장에 Source ID와 Evidence ID를 연결함.
7. 팀장 검토를 거쳐 승인된 원고만 통합함.
8. 최종본에서 안내문을 제거하고 수치·목차·증빙 페이지를 다시 대조함.

## 4. 공식 양식 및 작성방법 준수

- 공식 양식의 제목, 번호, 필수 표, 산식, 분량, 증빙 요구를 임의로 바꾸지 않음.
- 담당 목차의 모든 【작성방법】을 `writing_guidelines.csv`에 등록하고 충족 여부를 검토함.
- 2단 편집 PDF는 텍스트 추출 결과만 믿지 않고 페이지 이미지도 대조함.
- 적용 사업연도와 보고 기준기간이 확인되지 않으면 `확인필요`로 표시함.
- `[작성 후 삭제]` 안내는 내부 원장에는 보존하고 최종 제출본에서만 제거함.

## 5. 문체 규칙

- 기본 구조는 `□ 핵심 제목 → ◦ 주요 세부 실적 → - 세부 설명`으로 작성함.
- 계획·실행·성과·기여·환류의 흐름을 유지함.
- 종결은 `~함`, `~하였음`, `~되었음`, `~임`을 기본으로 통일함.
- 과장과 추측을 배제하고 확인된 수치, 기간, 참여 주체, 결과를 구체적으로 기술함.
- 완료·진행중·예정·확인필요·대상기간 외를 구분함.
- 다른 사업의 사례나 수치를 본 사업 실적으로 전용하지 않음.

## 6. 표와 수치 규칙

- 공식 양식의 표를 최우선으로 사용함.
- 모든 표에 기준기간, 단위, 출처, 관련 증빙을 확인함.
- 계획값, 변경계획값, 해당연차 실적, 누적실적을 혼합하지 않음.
- 공통 성과 수치는 `06_Shared_Data/02_Master_Metrics/master_metrics.csv`만 단일 원천으로 사용함.
- 서로 다른 값이 발견되면 임의로 고치지 않고 `issues.csv`에 기록한 뒤 원자료를 재확인함.
- 계산식, 반올림 방식, 분모·분자, 산정 기준일을 `metrics_validation_log.md`에 남김.

## 7. 출처와 증빙 규칙

- 원본을 확인하지 못한 주장을 확정 사실로 작성하지 않음.
- 작업 원고에는 `[근거: SRC-001 / 문서명 / p.00]`, `[증빙: EVD-001]` 형식을 사용함.
- 문서명, 작성기관, 작성일, 페이지, 시트·셀, 원본 경로를 레지스트리에 기록함.
- 원본 파일을 사용자 승인 없이 삭제·이동·이름 변경하지 않음.
- 받은 파일이 분류되지 않았으면 `01_Source_Documents/00_Inbox_Upload_Here/`에서 분석하고 권장 위치만 제시함.

## 8. 개인정보·재정정보 보호

- 학생·교원·직원·기업 담당자의 개인정보 원본은 공개용 산출물과 분리함.
- 원본 명단, 인사자료, 취업증빙, 계좌·급여·집행증빙은 `99_Private_Local/` 또는 Git 추적 제외 원본 폴더에서 관리함.
- 공개용 표에는 목적에 필요한 최소 정보만 사용하고 가능하면 집계값 또는 비식별 식별자를 사용함.
- 외부 공유, 업로드, Git 추적은 사용자가 명시적으로 승인한 안전한 문서에 한함.

## 9. 팀장 검토 절차

각 팀장은 다음 항목을 검토하고 `review_results.csv`에 실제 검토 결과를 기록함.

1. 공식 작성방법 충족 여부
2. 문장구조와 문체 통일
3. 사업계획과 실적의 연결성
4. 표의 완성도와 단위
5. 수치·산식의 정확성
6. 근거와 증빙의 정확성
7. 공통 수치의 팀 간 일치
8. 미확인 정보와 향후 계획의 명확한 구분

팀장 승인 상태가 아닌 원고는 최종 제출본에 통합하지 않음.

## 10. 파일 편집과 이력

- 기존 파일을 덮어쓰기 전에 변경 목적과 범위를 확인함.
- 중요한 변경은 `08_Review_and_History/03_Change_History/change_log.md`에 남김.
- 문제와 의사결정 필요사항은 `issues.csv`에 등록함.
- 실제 확인하지 않은 실적값을 예시 숫자로 채우지 않음.
